# Property description rules

Rules for writing hotel, apartment and venue descriptions for websites and booking sites. A booking-site description is often the first thing a guest reads, and the easiest place for a made-up detail to cause a complaint at check-in.

[`SKILL.md`](SKILL.md) turns these rules into a Claude skill. The rules work just as well as a brief for a copywriter.

## The rules

### 1. Only use verified sources

Every detail must come from something you can point to: the property's website, a fact sheet, an approved brochure, an existing listing or a link the team has shared. If it isn't in a source, it doesn't go in. No "likely has a lift", no "minutes from the beach" unless someone has measured it.

### 2. Don't drop anything from the source

If the source mentions it, keep it. Shorten the wording, never the facts, unless someone has asked for something to come out. Guests notice when the parking or the accessible room disappears from one listing but not another.

### 3. Lead with the neighbourhood

On booking sites and in short descriptions, open with where the property is and what's around it, then describe the property. Guests choose the area first and the building second.

> **Property-first:** A 40-room boutique hotel with a rooftop bar and gym.
>
> **Neighbourhood-first:** On a quiet street two minutes from the canal and the Saturday market, this 40-room hotel has a rooftop bar and gym.

### 4. Lock the structure once it's approved

When the order and format of a description have been signed off, don't change them in later drafts unless asked. Change the words inside the sections, not the sections themselves. That keeps every listing for a group consistent and makes reviewing quicker.

### 5. Flag gaps, don't fill them

If a booking site asks for something you don't have (check-in time, pet policy, nearest station), mark it **"To confirm"** and list it for the property team. Don't guess.

## Suggested structure

1. **Neighbourhood** - where it is, what's nearby, how to get there
2. **The property** - what it is and what makes it different
3. **Rooms** - types, sizes, what's in them
4. **Facilities** - food and drink, parking, gym, workspace, accessibility
5. **Practical details** - check-in and check-out, policies

## Before handing over

- [ ] Every detail traced to a source
- [ ] Nothing from the source left out
- [ ] Opens with the neighbourhood
- [ ] Approved structure unchanged
- [ ] Gaps marked "To confirm" and listed
- [ ] Within the booking site's character limit
